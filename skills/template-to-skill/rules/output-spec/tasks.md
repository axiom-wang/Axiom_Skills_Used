# 产出 SKILL 的 tasks/ 规范

## 01-generate-code.md（最重要的文件）

开头必须声明：
- 使用与参考实现相同的代码模版作为基础骨架（列出模版内置的骨架文件）
- 在此骨架基础上，以 reference/ 源码为基础进行定向修改

**核心方法论：按标注执行定向修改（非自主分析后重新创作）。** 下游 AI 读取 `reference/STRUCTURE_MAP.md` 中的逐文件标注，只对 🎨 标记的部分做替换，未标注部分保持原样。

必须包含的 7 个 section：

1. **执行哲学**："读取 STRUCTURE_MAP.md，只修改其中 🎨 标记的可定制部分，其余代码保持原样。面对每一行代码的默认决策是「保留」。"
2. **骨架声明**：列出已存在的骨架文件 + 需要额外安装的依赖
3. **三阶段工作流**：
   - Phase A：读取 `reference/STRUCTURE_MAP.md`，理解每个文件中哪些是 🎨 可定制部分、哪些是 📋 逻辑照搬部分、哪些是未标注（不可动）部分。结合用户需求，确定每个 🎨 标记部分的 target 值。
   - Phase B：按标注逐文件做精确替换——只改 🎨 标记的部分
   - Phase C：完整性检查——确认所有未标注为 🎨 的代码（尤其是 UI 结构）未被修改
4. **代码分层模型**：从当前模版实际情况定义 Layer 0-5 各层的具体内容（结构层、模式层、主题层、内容层、数据层、本地化层）。Layer 0-1 绝对不可修改，Layer 2-5 根据用户需求修改。
5. **STRUCTURE_MAP.md 的使用方式**：下游 AI 在 Phase A 中读取此文件，对每个 🎨 标记项确定 target 值（结合用户提示词和推断规则），然后在 Phase B 中逐项执行替换。标注之外的代码不可修改。
6. **修改规则 + 禁令**：颜色只换色系词保留色阶、文案精确替换不改结构、数据全链路一致、整块可定制区块可重新设计内部实现但保持外部接口和位置占比、📋 逻辑照搬直接复用模式只改字段名。禁止添加/删除/合并组件、禁止改 CSS 非颜色类、禁止改图表 type、禁止修改未标注的 UI 结构、禁止以"优化"为由偏离结构。
7. **完整性检查清单**：STRUCTURE_MAP.md 中每个 🎨 标记项都已正确替换、未标注部分未修改检查、CSS 形状未变检查、组件数量检查、import 一致性、数据全链路一致

**关键原则：不要在 01-generate-code.md 中包含场景化的映射表**（如"电商漏斗是 浏览→加购→下单"、"教育漏斗是 注册→试听→报名"）。定制清单的具体 target 值由下游 AI 在 Phase A 中结合用户需求和 STRUCTURE_MAP 标注得出，01-generate-code.md 只定义修改规则和检查标准。
