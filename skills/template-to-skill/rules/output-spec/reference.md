# 产出 SKILL 的 reference/ 规范

**核心定位**：reference/ 是下游 AI 执行定向修改的代码基底。下游 AI 在这些源码文件上按 STRUCTURE_MAP.md 的标注做精确替换，因此所有业务文件必须完整保留，不可裁剪。

## STRUCTURE_MAP.md（下游 AI 的核心执行指南）

来自 Phase 1 §1.5 的逐文件定制化标注。下游 AI 读取此文件后，只对 🎨 标记的部分做替换，未标注部分默认保留原样。

**格式规范**：

```markdown
## <文件路径>
功能：<一句话描述该文件在整体中的角色>

### 🎨 可定制
- L<行号>: <当前内容描述> → <定制方式>
- L<起始>-L<结束>: <区块描述> → <定制方式>
- 颜色类: <具体类名> → 可换色系词（保留色阶）

### 📋 逻辑照搬（仅逻辑文件需要此 section）
- <逻辑描述> → 直接复用，只改字段名

### 未标注部分全部保留原样
（<列出关键的不可动部分，如布局类名、区块排列等>）
```

**三类文件的标注策略**：

| 文件类型 | 标注策略 | 原因 |
|---------|---------|------|
| **UI 文件**（pages/\*、components/\*） | 逐块标注可改点（颜色类、文案字符串、可整块替换的区块），未标注部分 = 不可动 | 布局偏移的主战场，需要最高精度 |
| **数据文件**（data/\*） | 整体标记"保持 interface 结构，内容按新领域重写" | 不同领域内容完全不同，没法逐行保留 |
| **逻辑文件**（context/\*、hooks/\*） | 分情况：通用逻辑标记"📋 照搬模式"；领域特定逻辑标记"🎨 可定制" | 有些逻辑跨领域通用（加减数量、筛选排序），有些不是 |

**标注粒度**：

- **原子级**：单行文案、单个颜色类、单个标签文字
- **区块级**：整个图表区块可替换（但保持位置和占比）
- **文件级**：整个数据文件内容可重写（但保持 interface 结构）

**质量要求**：

- UI 文件：必须明确标出哪些行/区块可改，行号引用格式为 `L行号` 或 `L起始-L结束`
- 数据文件：标明 interface 中哪些字段名可改、哪些必须保留
- 逻辑文件：必须区分"📋 照搬"和"🎨 可定制"两类
- "未标注部分全部保留原样"这句话必须出现在每个 UI 文件标注的末尾

## CONTEXT.md 结构

```markdown
# 产品定义

## 功能清单
| 功能 | 说明 |

## 页面导航关系
哪些页面之间有跳转，触发条件是什么

## 视觉风格
一段话描述 + 关键数值表（字号/字重/间距/颜色）

## 数据结构
核心 TypeScript 类型定义

## 用户画像
谁在用、怎么提需求、AI 怎么响应
```

## 源码文件规则

- 放原始代码，不加占位符
- 保持原始目录结构（pages/ components/ data/ styles/）
- 所有业务文件完整保留，不做裁剪（下游 AI 需要在完整源码上执行定向修改）
