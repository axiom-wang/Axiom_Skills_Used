# 产出 SKILL 的 rules/ 规范

## architecture.md

包含：
- 路由结构表
- Provider 层级
- 核心数据类型定义（完整 interface）
- 组件职责表（名称 / 职责 / props）
- 模版内置骨架（直接沿用的文件列表）
- **可定制点清单**（见下方规范）

### 定制边界规范

architecture.md 中必须包含一个"定制边界"section，格式如下：

```markdown
## 定制边界（通用规则）

### 允许修改的层（仅限这些）

| 层 | 修改类型 | 约束 |
|----|---------|------|
| 颜色 | Tailwind 色系词替换 | 只改色系词，色阶保留；深色组件保持深色 |
| 文案 | 品牌名、导航文字、标题、标签 | 不改变文字所在的 HTML 结构 |
| 数据字段 | 实体名、字段名、枚举值 | 全链路一致（JSON↔Context↔Component） |
| 业务内容 | 漏斗阶段/分类/维度等 | 数量可增减，交互模式不可变 |
| 语言 | 界面文字翻译 | 日期/货币格式同步调整 |

### 不可修改（固定骨架）

- 页面布局结构（具体的 flex/grid 嵌套）
- 路由数量和路径结构
- 组件文件数量和拆分方式
- CSS 非颜色类（rounded-*、p-*、gap-*、w-*、h-*、shadow-*、space-*）
- HTML 嵌套层级
- Props 接口设计
- 图表类型配置
- 交互模式
```

定制边界从 Phase 1 的架构约束分析中得出，不包含场景化的具体值（不写"当前值: 蓝色系"这种硬编码内容）。

## design-system.md

包含：
- 编码规范摘要（import 顺序、组件格式、样式规则、lint 要求）
- **定制分析方法论**（辅助下游 AI 理解 STRUCTURE_MAP.md 标注的逻辑，非核心执行依据）：
  - 颜色分析：如何区分主色/强调色（可替换）vs 语义色/中性色（不替换）
  - 内容分析：如何识别品牌标识/导航文字/页面标题/数据标签等可替换字符串
  - 数据结构分析：如何从 Context/Store 和数据文件中提取实体定义/枚举值/指标
- **结构保真原则**：明确列出视为结构（不可修改）的代码类型
  - HTML 嵌套深度和层级关系
  - CSS 类名中的非颜色部分（形状、间距、布局）
  - 组件内部区块划分
  - 交互模式
  - 组件间引用关系和数据流向
- 推断规则（当用户未指定某些值时如何推断，优先级：用户显式声明 > 业务领域常识 > 保持与 reference 一致）
- AI 自主决策总原则（内部一致性 > 合理性 > 可用性 > 创造性）

**关键：下游 AI 的执行依据是 STRUCTURE_MAP.md 的逐文件标注，而非 design-system.md 中的方法论。** 方法论存在的目的是帮助下游 AI 理解标注背后的逻辑，以及处理标注未覆盖的边界情况。不包含场景化的映射表（如"品牌关键词→配色"、"业务类型→漏斗阶段"）。

**推断冲突解决优先级**（当多条推断规则产出矛盾结果时）：

```
用户显式声明 > 品牌定位推断 > 受众推断 > 领域默认值
```
