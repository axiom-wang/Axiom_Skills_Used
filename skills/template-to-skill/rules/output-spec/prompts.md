# 产出 SKILL 的 prompt-template.md 与 prompts/ 规范

## prompt-template.md

这是生成的 SKILL 的最终产出物之一——一段用户可以直接复制到 atoms.dev 对话框中使用的提示词模版。用户修改 `{{变量}}` 即可得到不同风格的产物，不需要了解 SKILL 内部结构。

**核心原则：提示词只讲业务和功能，不讲技术实现。**

用户是非技术人员，他们关心的是"我要一个什么样的网站"，而不是"代码怎么组织"。架构、组件结构、状态管理这些由 SKILL 内部处理，提示词不应暴露。

### 整体结构

```markdown
# Prompt Template: <模版名称>

## 变量说明

| 变量 | 含义 | 示例值 |
|------|------|--------|
| {{brand_name}} | 你的品牌名称 | "Moonlight Jewelry" |
| {{business_description}} | 一句话描述你的业务 | "手工银饰在线商店，主打极简设计" |
| {{language}} | 网站语言 | "中文" / "English" |
| ... | ... | ... |

## 提示词

---

帮我做一个叫 {{brand_name}} 的<业务类型>网站，{{business_description}}。语言用{{language}}。

需要这些功能：

<功能名> — <口语化描述，一句话说清楚用户能做什么、能看到什么>

<功能名> — <同上，描述交互和展示>

<功能名> — <同上>

整体风格 <感性描述，用形容词和氛围词>

---

## 使用说明

1. 复制上方两条 `---` 之间的内容
2. 将 {{变量}} 替换为你的实际信息
3. 粘贴到 atoms.dev 对话框中发送

### 调整技巧

- 想要深色风格？加一句"暗色主题"
- 想要更活泼的感觉？写"年轻活力，色彩丰富"
- ...（根据模版特性提供 2-3 个调整建议）
```

### 设计原则

1. **只用业务语言**：说"列表页"不说"listing component"，说"筛选功能"不说"filter state management"，说"加入XX"不说"context dispatch"
2. **功能描述从用户视角出发**：描述用户能看到和操作的东西，而不是代码层面的实现
3. **风格用感性词汇**：优雅、温暖、专业、活力、极简、奢华——这些是用户能理解和调整的维度
4. **变量从 SKILL.md 参数表推导**：必填参数对应必填变量，选填参数变为"调整技巧"中的自然语言引导
5. **使用说明面向零基础用户**：假设读者完全不了解技术，只想快速得到一个网站

### 提示词内容写法

提示词的核心是告诉 AI "我想要一个什么样的网站"，包含三个层面：

1. **是什么**（品牌信息）：品牌名、业务描述、目标用户
2. **有什么**（功能需求）：用户能看到的页面和功能，用日常语言列举
3. **像什么**（风格期望）：视觉感觉、情绪、氛围——用形容词和比喻，不用技术术语

**禁止出现的内容**：
- 技术栈名称（React、Tailwind、TypeScript、Vite）
- 代码相关术语（组件、状态管理、路由、hook、context）
- 文件结构描述（pages/、components/、data/）
- 构建和部署相关（build、lint、npm）
- CSS 具体数值（除非是用户能理解的"圆角"、"阴影"等视觉描述）

### 插值语法规范

- 使用 `{{variable_name}}` 格式（双花括号 + 下划线命名）
- 变量名与 SKILL.md 参数表中的参数名保持一致
- 可选变量用 `{{?optional_var}}` 标记，或在使用说明中注明可删除
- 多选项变量用 `{{style: option_a | option_b | option_c}}` 格式提示可选值

## prompts/ 规范

prompts/ 目录包含 3 个基于 prompt-template.md 生成的即用型提示词文案，所有变量已填充为具体值。用户可以直接复制其中任意一个到 atoms.dev 使用。

### 文件结构

每个文件（prompt-1.md、prompt-2.md、prompt-3.md）只包含纯提示词内容，不加标题、描述或分隔线——用户直接全选复制即可：

```markdown
帮我做一个叫 XX 的 YY Dashboard。ZZ界面。

需要这些功能：

...
```

不要加 `# 标题`、`> 描述`、`---` 分隔线等任何非提示词内容。文件内容 = 用户要复制的内容，一字不多。

### 选题策略

3 个提示词应体现模版的**适用范围**而非相似用法：

| 编号 | 定位 | 目的 |
|------|------|------|
| prompt-1 | 最贴近原模版风格的典型案例 | 让用户快速理解"这个模版能做什么" |
| prompt-2 | 行业/风格明显不同的变体 | 展示模版的弹性和适配能力 |
| prompt-3 | 偏极端或创意方向的变体 | 展示模版的表现上限 |

### 质量要求

- 变量填充值要**具体且有画面感**：不是 "My Brand"，而是 "Moonlight Ceramics"、"Velocity Racing Gear"
- 填充的值要能引导 AI 产出**视觉差异明显**的结果
- 3 个提示词之间的差异应体现在：品牌调性、风格方向、目标用户、功能侧重等维度
- 每个提示词是**独立完整**的，用户不需要参考 prompt-template.md 就能直接使用
- 所有内容使用业务语言，不出现任何技术术语
- **布局一致性由 SKILL 内部保证**：生成的 tasks/01-generate-code.md 和 rules/architecture.md 会锁定布局结构为不可变骨架，prompt 中不需要重复描述布局约束。prompt 只需关注业务差异化内容（品牌、行业、功能侧重、风格偏好）。

### 语气风格（极重要）

提示词要像**用户在对话框里打字**，不是写技术文档。

**正确的语气**：
```
帮我做一个电商转化分析的 Dashboard，主要看用户从广告点击到付费的整个过程。

转化漏斗 — 路径是 广告点击→浏览→注册→付费，每步显示人数和转化率，能按渠道对比看。

流失分析 — 每个阶段走了多少人，这些人什么画像，能导出名单做召回。
```

**错误的语气**（像文档/规格书）：
```
请开发一个完整的数据分析 Dashboard 应用，核心功能包括：

1. **转化漏斗分析** — 自定义转化路径（广告点击→浏览→注册→付费），展示各阶段用户数和转化率，支持按渠道/设备对比分析
2. **流失分析** — 各阶段流失率图表 + 流失用户画像（年龄/设备/来源）+ 可导出用户列表
```

**具体规则**：
- 用"帮我做一个..."开头，不用"请开发..."
- 品牌名、领域描述、语言等参数要**融入自然语句**中，不要单独成行列出像填表（错误：`品牌名\n描述\nLanguage: 中文`；正确：融入开头那句话里）
- 功能描述用"功能名 — 口语化描述"格式，不加编号、不加粗体
- 用口语："能按渠道分开对比看"而不是"支持按渠道对比分析"
- 用短句拆解功能，不用长定语从句
- 不用"支持X"这种产品文档腔，改为"能X"或直接描述做什么
- 保持信息量完整，但让每句话都像在跟人说话
