## 适用场景

- "帮我生成今天的公司简报" / "今天公司发生了什么"
- "飞书简报" / "每日简报" / "公司动态摘要"

- "我想了解公司整体项目、风险、决策和团队动态"

## 安全与合规规则（必须遵守）

1. **只访问有权限的内容**：只调用用户已授权的 API，不绕过飞书权限控制
2. **不批量导出聊天记录**：每次只获取指定日期范围内的消息，不批量导出历史
3. **不保存敏感原文**：简报中不复制完整消息原文，只保留可追溯的摘要、群名和时间
4. **完全移除个人视角**：
   - 不访问 P2P 私人会话
   - 不拉取个人任务
   - 不拉取个人日程
   - 不搜索个人发言
   - 不生成个人待办或个人复盘
5. **脱敏规则**：
   - 薪酬、绩效、人事变动 → 只写"有人事/薪酬相关讨论，详见原始消息"
   - 客户敏感信息（客户名称、合同金额、商业条款）→ 用"某客户"和"具体金额已脱敏"替代
   - 私人聊天内容 → 不访问、不分析、不输出
   - 未公开的人名角色变化 → 只写"相关负责人/相关团队"，不展开个人隐私
6. **不发送到外部系统**：简报内容不发到第三方服务

## 执行流程

### Step 1：确定时间范围

默认生成当天公司态势简报。若用户说"昨日"、"昨天"、"本周某天"，按用户指定日期计算 UTC+8 时间范围。

```bash
# 获取今天日期（用于标题）
date +%Y-%m-%d

# 计算今日 UTC+8 时间范围（ISO 8601）
python3 -c "
from datetime import datetime, timezone, timedelta
tz = timezone(timedelta(hours=8))
now = datetime.now(tz)
start = now.replace(hour=0, minute=0, second=0, microsecond=0)
end = now.replace(hour=23, minute=59, second=59, microsecond=0)
print(f'START={start.isoformat()}')
print(f'END={end.isoformat()}')
print(f'TODAY={now.strftime(\"%Y-%m-%d\")}')
print(f'WEEKDAY={[\"星期一\",\"星期二\",\"星期三\",\"星期四\",\"星期五\",\"星期六\",\"星期日\"][now.weekday()]}')
"
```

### Step 2：并行拉取公司态势数据

以下命令尽可能并行执行。核心策略是"重点群 + 关键词"，不使用个人数据源。

#### ① 重点群消息（核心数据源）

读取 `config.yaml` 中的 `priority_chats` 列表，对每个重点群单独拉取消息。每个重点群必须配置 `id`、`name`、`category`，category 建议使用：

```
project / announcement / management / business / engineering / incident / operation / other
```

```bash
lark-cli im +chat-messages-list \
  --chat-id "<oc_xxxx>" \
  --start "YYYY-MM-DDT00:00:00+08:00" \
  --end   "YYYY-MM-DDT23:59:59+08:00" \
  --format json \
  --page-size 50
```

如果返回 `page_token`，继续用下一页令牌拉取，直到无下一页或达到配置中的 `fetch.max_messages_per_chat`。

若没有配置 `priority_chats`：

- 继续执行关键词搜索
- 在简报末尾注明"未配置重点群，重点项目覆盖可能不足"
- 不回退到个人消息、个人任务或个人日程

#### ② 公司级关键词搜索（补充发现）

从配置文件读取关键词分组；若无配置，使用内置默认词。每个 query 必须保持简短，避免 Lark 搜索 `query` 最大长度限制。不要把所有关键词拼成一个长 query。

推荐分组：

```text
项目词：DeepFlow Atoms AppWorld MGX 数据增长
风险词：故障 回滚 阻塞 延期 风险 P0 P1 紧急 数据异常
决策词：决定 确认 定了 方案 评审 里程碑 负责人变更
发布词：上线 发布 提测 灰度 合并 revert LGTM CR
业务词：客户 商机 合同 续费 交付 南航 需求变更
```

对每个短 query 执行：

```bash
lark-cli im +messages-search \
  --chat-type group \
  --query "<短关键词组>" \
  --start "YYYY-MM-DDT00:00:00+08:00" \
  --end   "YYYY-MM-DDT23:59:59+08:00" \
  --page-all \
  --page-size 50 \
  --format json
```

关键词搜索只用于公司态势发现；必须过滤屏蔽群，必须与重点群消息按 `message_id` 去重。

#### ③ 近期文档更新（可选）

当配置 `fetch.fetch_drive_updates: true` 且权限允许时，查看用户有权限访问的最近更新文档。

```bash
lark-cli drive files list \
  --params '{"order_by":"edit_time","page_size":20}' \
  --format json
```

若 drive 权限不足，跳过该数据源，并在"数据源限制"中注明。

> **禁止的数据源**：
> - 不使用个人提及搜索
> - 不按个人发送人检索
> - 不使用 P2P 私人会话搜索
> - 不读取个人待办
> - 不读取个人日历

> **权限降级策略**：
> - 若 `search:message` 未授权 → 只读取 `priority_chats`
> - 若 `priority_chats` 未配置且 `search:message` 不可用 → 生成"数据不足，无法可靠了解公司态势"的限制说明，不回退到个人消息
> - 若 drive 权限不足 → 跳过文档更新步骤
> - 记录所有跳过的数据源和原因

### Step 3：数据预处理

对原始数据执行以下处理：

**消息清洗规则（低优先级过滤）：**
- 丢弃：纯表情回复、"+1"、"收到"、"ok"等无信息量回复
- 丢弃：系统机器人的重复通知（canary 冻结、CI 循环结果、监控重复告警）
- 丢弃：消息正文少于 10 个字符且无附件、无链接、无明确项目词的消息
- 丢弃：与公司运行无关的活动闲聊、餐饮出行、非业务娱乐通知
- 保留：含链接、文档、项目名、风险词、决策词、发布词、客户/业务词、跨团队依赖的消息

**高优先级关键词（自动标记 ⭐）：**
```
上线、发布、灰度、回滚、故障、数据异常、延期、阻塞、风险、紧急、
决定、确认、定了、deadline、截止、审批、客户、交付、需求变更、
里程碑、负责人变更、跨团队、依赖、P0、P1、CR、LGTM、revert
```

**公司态势分类：**
- 公司级进展：产品、业务、平台或组织层面的明确推进
- 项目/产品动态：具体项目、产品模块、PRD、研发、测试、发布、交付
- 重要决策：方向确定、方案确认、资源/负责人变化、里程碑变化
- 风险阻塞：故障、延期、阻塞、数据异常、客户交付风险、架构风险
- 跨团队依赖：多个团队协作、接口/API/数据依赖、上下游交接
- 客户/市场信号：客户反馈、交付、续费、商机、竞品、业务需求变化
- 运营/数据异常：指标异常、同步缺数、监控异常、数据口径变化
- 团队运行动态：团队工作方向、会议结论、协作方式变化

**消息去重：**
- 同一条消息在多个 API 返回中出现 → 只保留一份
- 相同主题连续出现的消息 → 合并为一条摘要
- 同一主题跨群出现 → 在"被反复提及的主题"中统计群数和出现次数

**群组分类（优先使用配置）：**
- 优先使用 `priority_chats[].category`
- 未配置时基于群名称推断：
  - 含"项目"、"PRD"、"开发"、"研发"、"技术"、"Core"、"Dev" → 项目/工程群
  - 含"公告"、"通知"、"全员" → 公告群
  - 含"运营"、"市场"、"销售"、"增长" → 业务群
  - 含"管理"、"HR"、"行政" → 管理群
  - 含"故障"、"应急"、"事故"、"监控" → 事件/风险群
  - 其他 → 其他群

### Step 4：AI 综合分析

将 Step 2 收集的数据整合，按以下维度分析：

**项目识别**：从群名、文档名、链接标题、消息中反复出现的名词提取项目名称。

**影响范围识别**：判断事件影响公司整体、某产品线、某项目、某团队、客户/交付，还是仅局部流程。

**事件分类**：
- 决策类：含"决定"、"确认"、"定了"、"按这个走"、"最终方案"
- 风险类：含"阻塞"、"延期"、"问题"、"故障"、"异常"、"回滚"、"P0/P1"
- 进展类：含"完成"、"上线"、"提测"、"发布"、"合并"、"部署"
- 依赖类：含"需要 API"、"依赖"、"对齐"、"联调"、"跨团队"
- 业务类：含"客户"、"商机"、"交付"、"续费"、"合同"、"竞品"

**话题聚类**：找出在多个群里同时出现或同一天反复出现的主题，推断其公司级含义。

**重要性排序**：
1. 公司级事故、客户交付、发布/回滚、明确决策
2. 多团队依赖和会影响里程碑的风险
3. 重点项目/产品进展
4. 业务、客户、市场和竞品信号
5. 团队运行动态

## 权限要求

### 必须的权限（最小集）

| scope | 用途 |
|-------|------|
| `im:message:readonly` | 读取重点群消息 |
| `im:chat:readonly` | 获取群列表和群信息 |
| `search:message` | 全局群消息关键词搜索 |

### 推荐的权限（更完整简报）

| scope | 用途 |
|-------|------|
| `drive:drive:readonly` | 读取文档更新 |
| `space:document:retrieve` | 读取云文档列表或详情（视 CLI 实际提示授权） |
| `contact:user.base:readonly` | 解析消息发送人的真实姓名 |

### 授权方式

首次使用前执行：

```bash
# 最小权限授权
lark-cli auth login --scope "im:message:readonly im:chat:readonly search:message"

# 推荐完整授权
lark-cli auth login --scope "im:message:readonly im:chat:readonly search:message drive:drive:readonly space:document:retrieve contact:user.base:readonly"
```

## 错误处理

| 错误类型 | 处理方式 |
|---------|---------|
| `permission_violations` | 提示用户执行对应授权命令，跳过该数据源，继续生成简报 |
| `search:message` 未授权 | 降级为只读取 `priority_chats` |
| `priority_chats` 未配置且 `search:message` 不可用 | 生成"数据不足，无法可靠了解公司态势"的限制说明，不回退到个人消息 |
| 重点群消息为空 | 标注"该群今日无消息"，继续处理其他来源 |
| 飞书服务超时 | 重试一次，超时则跳过该数据源并在简报末尾注明 |
| drive 权限不足 | 跳过文档更新步骤，并在"数据源限制"中注明 |
| `config.yaml` 不存在 | 使用内置关键词，标注重点群覆盖不足 |
